# Pool Wait Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When every model of a role's pool is down, the pool waits for one to come back, up to a total budget (120 s
by default), instead of losing the decision, review or chat answer.

**Architecture:**
- `PoolModel.request` (src/pilot/modelguard.py) loops while `ordered()` is empty. Each time round it sleeps until
  whichever comes first:
  - the earliest open breaker's window;
  - a 2 s poll, while a model's trial runs elsewhere.
- It stops when the request's waiting reaches `pool_max_wait_s`, or when the owner's `stopping()` says so.
- `Hooks` gains `stopping` and `on_wait`; `event_hooks` emits `model_wait`; the dashboard shows it.

**Tech Stack:** Python 3.13, anyio (the guard's `_sleep`), aiohttp dashboard page (vanilla JS), pytest + Playwright UI
tests.

**Spec:** docs/design/2026-10-06-pool-wait-design.md (rulings 1-5).

## Global Constraints

- **`pool_max_wait_s`:**
  - default `120.0`;
  - environment `PILOT_POOL_WAIT_S` (a number ≥ 0; anything else raises `ValueError` naming `PILOT_POOL_WAIT_S`);
  - `0` means fail at once.
- **Poll steps:** `POOL_POLL_S = 2.0` is the step while a trial runs elsewhere. `POOL_STOP_STEP_S = 1.0` is the longest
  single sleep between `stopping()` checks.
- **The `model_wait` event's fields:**
  - `role`;
  - `models` (a list of names);
  - `seconds` (this sleep);
  - `waited_s` (so far in this request);
  - `budget_s`;
  - `reason`: either `"every model is overloaded"`/`"no model is available"`, or `"a trial is running on <model>"`.
- **The `PoolExhausted` cause on a stop:** `"stopped while waiting"`.
- **Version:** bump `pyproject.toml` `version` to `0.1.1`, so CI publishes a new immutable tag.
- **Commits** go only through `scripts/ci-commit.sh` with conventional messages. No AI or assistant attribution.
- **UI tests:** a commit that stages `src/pilot/static/*.html` needs `.venv/bin/pytest -q -m ui tests/ui` to have run.
- **Live data:** never run `.venv/bin/python -m pilot ...` against live data (tests use temp dirs).

## Review Focus

1. **A stop during a long wait.** A page Stop or a container stop must end the wait within about a second. It must not
   hold the container past its 40 s stop grace. Test: Task 1, `test_a_stop_ends_the_wait`.
2. **A pool whose trial keeps failing.** Each failed trial doubles the window. The total wait must still end at the
   budget, not grow with it. Test: Task 1, `test_the_wait_ends_at_the_budget_however_windows_move`.
3. **Two roles at once.** Chat waits for the trial the decision holds and gets the answer once the trial succeeds; it
   must not raise at once. Test: Task 1, `test_a_second_request_waits_for_a_running_trial`.
4. **Old behaviour on demand.** `PILOT_POOL_WAIT_S=0` raises at once, as before ruling 11. Test: Task 1,
   `test_no_budget_fails_at_once`.
5. **The wait is visible.** A `model_wait` in Activity and on the Deciding card. Test: Task 2, the UI test.

```python
POOL_POLL_S = 2.0          # while another request holds a model's trial, look again this often
POOL_STOP_STEP_S = 1.0     # the longest single sleep between stop checks (rulings 1 and 3)

    # inside PoolModel.request, replacing the `if not order:` block (ruling 11 of the model guard design,
    # amended by the pool-wait design):
            if not order:
                rest = [self.guarded[i].name for i in self._order if i not in done]
                names = [gm.name for gm in self.guarded]
                states = {n: self.health.status(n) for n in names}
                now = self.health.clock()
                budget = self.health.cfg.pool_max_wait_s
                reopen = self.health.earliest_reopen(names)
                running = [n for n, st in states.items() if st == "half_open"]
                if all(st == "broken" for st in states.values()) or budget <= 0:
                    raise PoolExhausted(self.role, tried, rest)
                due = []
                if reopen is not None:
                    due.append(max(0.0, reopen - now))
                if running:
                    due.append(POOL_POLL_S)
                if not due or waited_s >= budget:
                    raise PoolExhausted(self.role, tried, rest)
                step = min(min(due), budget - waited_s)
                reason = (f"a trial is running on {running[0]}" if running and (reopen is None or reopen - now > POOL_POLL_S)
                          else "every model is overloaded" if any(u.failure.kind == OVERLOADED for u in tried)
                          else "no model is available")
                self.hooks.on_wait(models=names, seconds=round(step, 1), waited=round(waited_s, 1), reason=reason)
                slept = 0.0
                while slept < step:
                    if self.hooks.stopping():
                        raise PoolExhausted(self.role, tried + [ModelUnavailable(names[0], Failure(OTHER, None, None,
                                                                 "stopped while waiting"))], rest)
                    chunk = min(POOL_STOP_STEP_S, step - slept)
                    await _sleep(chunk)
                    slept += chunk
                waited_s += step
                done = {i for i in done if self.health.status(self.guarded[i].name) not in ("trial", "closed")}
                continue
```

  Implementation notes:
  - Initialise `waited_s = 0.0` where `waited = False` was, and remove `waited`.
  - Read how `PoolExhausted` builds its causes (`tried`, `rest`) and keep the "stopped while waiting" cause consistent
    with `describe()`. If a synthetic `ModelUnavailable` reads oddly, add an explicit `stopped` flag to
    `PoolExhausted` and have `causes()` add `{"model": "-", "error": "stopped while waiting"}`.
  - Check that `Failure`, `OTHER` and `OVERLOADED` are the names in this module.
  - `Hooks` gains `on_wait: Callable[..., None] = _noop` and `stopping: Callable[[], bool] = lambda: False`. Keep the
    dataclass field order backward compatible: append the new fields at the end.
  - `event_hooks(..., stopping=None)` passes `stopping or x.stopping`, and its `on_wait` calls
    `x.on_wait(...)` and then `emit("model_wait", role=role, models=models, seconds=seconds, waited_s=waited,

    of `on_wait` (preferred: `on_wait(models, seconds, waited, budget, reason)`) or emit it from the pool. Choose one,
